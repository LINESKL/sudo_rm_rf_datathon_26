## Бэк и деплой

### B1. Каркас FastAPI, контракт и заглушка детектора
Блокирует: F1, F2, B2. Срок: 17:00.

**Где именно на сайте**
API: `POST /api/v1/analyze`, `GET /api/v1/jobs/{id}`, `GET /api/v1/jobs/{id}/details`, `GET /health`; корень `/` отдаёт фронт.

**Где именно в коде**
`backend/app/main.py`, `backend/app/schemas.py`, `backend/app/auth.py`, `ml/stub.py` (сигнатура `analyze(video_path, deadline_s, on_progress) -> AnalysisResult`).

**Что нужно доработать**
- Pydantic-модели ответа жюри **строго** по ТЗ: `job_id, status, verdict, violations[type, timecode_sec, description, evidence_frames[timestamp_sec, image_base64]]`. Никаких лишних ключей.
- Модель `/details`: `progress {stage, value}`, по нарушениям `type_id, confidence, timecode_end_sec, rule {document, point, quote, url}`, плюс `timeline`, `processing_sec`, `preview_url`.
- Зависимость `X-API-Key` на всех `/api/*`: ключ из env `API_KEY`, без ключа или с неверным — `401`.
- `ml/stub.py`: через 5 с возвращает одно фейковое нарушение с реальным кадром из видео (ffmpeg, JPEG → base64).
- Статика `frontend/` на `/`, CORS для локальной разработки.

**Критерии приёмки**
- [ ] `curl -X POST .../api/v1/analyze -H "X-API-Key: …" -F "file=@X-1.mov"` возвращает `job_id`.
- [ ] Через ~5 с `GET /api/v1/jobs/{id}` отдаёт `done` и JSON, совпадающий со схемой ТЗ ключ в ключ.
- [ ] Запрос без ключа получает `401`.
- [ ] Фронт открывается по `/`.

### B2. Очередь задач, SQLite и прогресс
Зависит от B1. Блокирует B5. Срок: 20:00.

**Где именно на сайте**
`GET /api/v1/jobs/{id}` (статусы) и `/details` (прогресс).

**Где именно в коде**
`backend/app/queue.py`, `backend/app/store.py`, `backend/data/jobs.db`.

**Что нужно доработать**
- asyncio-очередь, 3 воркера; тяжёлая работа `ml.analyze` в отдельном потоке или процессе, event loop не блокируется.
- SQLite (WAL): `jobs(id, status, created_at, started_at, finished_at, result_json, details_json, error)`.
- При старте сервиса задачи в статусе `processing` возвращаются в очередь.
- `on_progress(stage, value)` из пайплайна пишется в `details.progress`.
- Жёсткий таймаут 280 с на задачу: по таймауту `failed` с причиной.

**Критерии приёмки**
- [ ] 6 задач, отправленных разом, выполняются по 3 параллельно, все доходят до `done`.
- [ ] После `kill` и рестарта незавершённые задачи доделываются.
- [ ] `/details` показывает смену этапов.

### B3. Приём видео и h264-превью
Зависит от B1. Блокирует F3. Срок: 20:00.

**Где именно на сайте**
Загрузка в `POST /api/v1/analyze`, превью по `preview_url` из `/details`.

**Где именно в коде**
`backend/app/video.py`, `backend/data/uploads/`, `backend/data/previews/`.

**Что нужно доработать**
- Валидация: расширение `.mov`/`.mp4`, размер до 200 МБ, `ffprobe` открывает видеопоток; иначе `400` с понятной причиной.
- Превью для браузера: `ffmpeg -c:v libx264 -preset veryfast -crf 28 -movflags +faststart` (исходник может быть HEVC).
- Раздача превью через статический роут с поддержкой Range-запросов (перемотка в плеере).

**Критерии приёмки**
- [ ] Битый файл и `.avi` получают `400`.
- [ ] Превью любого ролика из датасета играет в Chrome и Safari, перемотка работает.

### B4. Деплой: RunPod, Docker, vLLM, публичный URL
Зависит от B1. Блокирует B5. Срок: заглушка снаружи к 00:00, реальный пайплайн к 04:00.

**Где именно на сайте**
Публичный HTTPS-адрес сервиса — его сдаём жюри.

**Где именно в коде**
`Dockerfile`, `deploy/start.sh`, `deploy/README.md`.

**Что нужно доработать**
- Под RunPod (Secure Cloud) с RTX 4090, публичный HTTPS-порт сервиса, persistent volume под данные и веса.
- Один образ: FastAPI + vLLM (`vllm serve` на `localhost:8001`, наружу не открыт), ffmpeg, веса в образе или на volume.
- `start.sh` поднимает vLLM, ждёт готовности, затем uvicorn.
- Скрипт подъёма с нуля на новом поде за ≤ 15 мин (на случай падения хоста).
- Модель уточняет ML после спайка: `Qwen/Qwen3.5-9B` или `Qwen/Qwen3-VL-8B-Instruct`.

**Критерии приёмки**
- [ ] С внешней машины `curl` по публичному URL проходит сценарий B1.
- [ ] После рестарта пода сервис поднимается сам.
- [ ] `/health` показывает GPU, vLLM и место на диске.

### B5. Нагрузка и офлайн-проверка

**Где именно на сайте**
Боевой URL.

**Где именно в коде**
`deploy/loadtest.py`.

**Что нужно доработать**

- Офлайн: контейнер с `--network none` (или `HF_HUB_OFFLINE=1`, `TRANSFORMERS_OFFLINE=1`) обрабатывает видео без сети.

**Критерии приёмки**
- [ ] Каждое из 6 видео укладывается в 5 мин от загрузки до `done`.
- [ ] Без сети обработка проходит, в логах нет сетевых обращений.

## Фронт

### F1. Загрузка видео и статус обработки
Работает на заглушке B1 (до её готовности — на мок-JSON). Срок: 17:00.

**Где именно на сайте**
Главная `/`: состояния «Загрузка» → «Обработка».

**Где именно в коде**
`frontend/index.html`, `frontend/app.js`, `frontend/styles.css`, `frontend/api.js`.

**Что нужно доработать**
- Без сборки и CDN: чистые HTML, CSS и JS (сервис должен работать офлайн). Шрифты системные.
- Drag-and-drop и выбор файла, проверка `.mov`/`.mp4` и размера на клиенте, прогресс отправки (XHR `upload.onprogress`).
- Ключ API: поле ввода с запоминанием в `localStorage`, ключ уходит в заголовке `X-API-Key`.
- Опрос `/details` раз в 1,5 с, этапы: декодирование → люди и предметы → анализ сцены → проверка находок.
- Ошибки: `400`, `401`, `failed`, обрыв сети — понятные сообщения и кнопка «Попробовать снова».

**Критерии приёмки**
- [ ] Загрузка ролика из датасета доходит до экрана результата на заглушке.
- [ ] Неверный ключ показывает сообщение, страница не падает.

### F2. Экран результата: вердикт и карточки нарушений
Зависит от формата `/details` (B1). Срок: 20:00.

**Где именно на сайте**
Главная `/`, состояние «Результат».

**Где именно в коде**
`frontend/result.js`, `frontend/styles.css`.

**Что нужно доработать**
- Баннер вердикта: «Нарушение не обнаружено» (нейтральный) или «Обнаружены признаки возможных нарушений» (акцентный), число нарушений.
- Карточка нарушения: тип, таймкод `мм:сс,д`, 1–3 кадра (клик — увеличение), блоки «Что видно» и «Почему это может быть нарушением», норматив: документ, пункт, цитата, ссылка на adilet, индикатор уверенности.
- Плашка «Результат — подсказка для проверки человеком, не заключение».
- Кнопка «Проверить другое видео».

**Критерии приёмки**
- [ ] Видео с 0, 1 и 3 нарушениями отображаются корректно.
- [ ] Длинные тексты и отсутствие норматива не ломают вёрстку.

### F3. Плеер с метками нарушений
Зависит от B3 (`preview_url`). Срок: 00:00.

**Где именно на сайте**
Экран результата, над карточками.

**Где именно в коде**
`frontend/player.js`.

**Что нужно доработать**
- `<video>` по `preview_url`; под ним шкала с метками нарушений по `timecode_sec`–`timecode_end_sec`.
- Клик по метке или таймкоду в карточке переводит видео к моменту (−1 с) и подсвечивает карточку.

**Критерии приёмки**
- [ ] Клик по таймкоду в карточке перематывает видео с точностью до 0,5 с.

### F4. Дорожки таймлайна состояний
Зависит от формата `timeline` в `/details` (B1, мок). Срок: 04:00.

**Где именно на сайте**
Экран результата, под плеером.

**Где именно в коде**
`frontend/timeline.js`.

**Что нужно доработать**
- Дорожки-интервалы под шкалой видео: «Кассир на месте», «Деньги на столе», «Сейф открыт», «Экран разблокирован», «Посторонний в зоне кассира» (список берётся из ключей `timeline`).
- Синхронный курсор с плеером, клик по дорожке — перемотка.

**Критерии приёмки**
- [ ] На мок-данных видны все дорожки, курсор двигается вместе с видео.

Срок: 08:00.
