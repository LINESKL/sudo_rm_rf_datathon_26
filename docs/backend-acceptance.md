Рабочая ветка: `dunan/backend-video-processing`. Проверялся backend со своим
`ml.stub:analyze`; результаты ниже не являются оценкой качества детектора.
По указанию владельца текущий этап выполняется без ещё не опубликованного фронтенда.

Среда: Windows, Python 3.13.2, FFmpeg 9.0.2. HTTP-проверки всех файлов выполнялись
по три одновременно на локальном сервере. Изначальные MOV имеют H.264;
HTTP-приёмка каждого файла заняла 7,429–14,324 с, включая загрузку и очередь.
Для браузерного теста использовался обычный HTML video на origin backend;
это проверка media, а не ещё не опубликованного интерфейса команды.
HEVC проверен отдельным сгенерированным MOV в интеграционном тесте.
Синтетический MOV 29 492 065 байт отдельно проверен в чистом окружении:
HTTP-приёмка заняла 6,977 с, Chrome 155.0.8059.39 воспроизвёл его и перемотал на 2,4 с.

Отчёты с хешами исходников и агрегатами находятся локально в
`test-results/dataset/summary.json`, по одному файлу — в `test-results/dataset/NN.json`.
Результат Chrome по всем роликам — `test-results/dataset/chrome.json`.
Синтетический прогон: `test-results/fresh-http.json`, `test-results/chrome-preview.json`.
Видео, кадры и локальные результаты не добавляются в Git. В отчёт HTTP-приёмки
не записываются API-ключи, cookie и JPEG.

## Как повторить

Запустить сервис по README, установить API_KEY в клиентской оболочке и выполнить:

```bash
python -m deploy.acceptance --url http://127.0.0.1:8000 --source dataset /path/to/video.mov
```

Проверка возвращает ненулевой код при ошибке. Нужен ffprobe в PATH либо FFPROBE_BIN.
Для реального ML добавить `--require-real`: заглушка и отсутствие явного
`degraded=false` не проходят. Флаг проверяет режим и контракт; он не доказывает
качество ML и не заменяет проверку используемых моделей.
При нескольких роликах использовать разные пути `--output`, чтобы сохранить каждый отчёт.
