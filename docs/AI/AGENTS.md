# Общие правила GuardTusk

- Сначала прочитайте продуктовый бриф и canonical sources через README этого каталога.
- Frontend принадлежит `frontend/`. Это React + Vite приложение, результат сборки раздаёт backend с того же origin. Не добавляйте отдельный сервер рендеринга.
- Реальный API-формат задают `backend/app/schemas.py`, сериализация `ml/types.py` и спецификация. `docs/frontend/mock_details*.json` — примеры для явного демо. Типы и runtime-проверка frontend находятся в `frontend/src/api/`; не меняйте wire contract ради интерфейса.
- Соблюдайте русский язык, светлый стиль и токены брифа. Общие стили находятся в `frontend/src/styles.css`, локальный Open Sans — в `frontend/src/assets/fonts/`. Не используйте CDN, аналитику и внешние шрифты в runtime.
- Для элементов управления используйте существующие shadcn/ui-компоненты из `frontend/src/components/ui/`. Набор настроен через `frontend/components.json` (new-york, Radix), Tailwind подключён к Vite. Добавляйте компоненты только под реальную функцию; не создавайте параллельные кнопки, поля и другие UI-примитивы.
- Исходники shadcn/ui принадлежат проекту и доступны для редактирования. Сохраняйте alias `@/` из TypeScript/Vite и принятые импорты утилит компонентов. Каноническая светлая тема находится в shadcn-переменных `frontend/src/styles.css`; старые layout-переменные только ссылаются на неё. Цвет бренда — `--brand`, мягкая подсветка — `--accent`.
- Сохраняйте минимальный интерфейс: компактная шапка GuardTusk, заголовок «Проверка видео» и одна рабочая колонка для загрузки, API-ключа, статуса и результата. Добавляйте только функциональность задач Linear и примечание о проверке человеком; без рекламного hero, боковых преимуществ и большого footer.
- Обязательный результат — карточки каждого события с точным таймкодом, 1–3 JPEG, наблюдением, объяснением и источником. F4 (дорожки состояний) — дополнение после основной приёмки; F3 (плеер) не должен блокировать доказательства. Ошибку или неполноту нельзя выдавать за отсутствие нарушений. Разбор кейса и приоритеты — `docs/frontend/case-analysis.md`.
- Визуальный референс Forte задаёт палитру, типографику и скругления из брифа. Название и логотип банка, навигация и банковские продукты не входят в интерфейс GuardTusk.
- Демо работает только при явно выбранном режиме. Production должен обращаться к backend и показывать его ошибки; автоматически подменять неудачный анализ примером запрещено.
- `/health` сообщает режим `stub/pipeline`; тестовый или неподтверждённый режим и `details.degraded` показывайте явно. Отсутствующие `rules_checked`, `point`, `quote` или `rule` не заменяйте выдуманными значениями. Не обещайте качество ML по успешному HTTP или наличию кода.
- Реальный ключ не помещайте в source, env сборки, логи или тестовые артефакты. Пользовательский ключ передаётся в заголовке и сохраняется только в браузере по требованию F1.
- Существующий ключ `localStorage` — `cashguard-api-key`; смена имени продукта не должна сбрасывать сохранённый доступ.
- Перед завершением frontend-изменений выполните scripts `lint`, `test`, `build` из `frontend/package.json`, проверьте затронутые состояния в браузере и адаптив. Разделяйте тесты на моках и приёмку с реальным backend.
- Сохраняйте изменения backend/ML других участников. Пользователь разрешил объединить ветки и необходимые доработки интеграции; не меняйте алгоритмы ML без конкретной задачи. Не добавляйте зависимости или слои без потребителя. Commit/push — по прямому запросу.
