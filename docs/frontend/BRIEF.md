# Бриф фронтенда GuardTusk

Здесь только **что** нужно и **почему**. Обязательность кейса отделена от решений пользователя и команды
в [разборе PDF и задач](case-analysis.md). Пользователь проверил план и разрешил продолжить разработку с F0/F1.
Выполненные проверки и открытая интеграция — в [отчёте приёмки](acceptance.md).
Ограничения **[жёстко]** включают требования кейса и принятые решения проекта.

Контекст: `docs/superpowers/specs/2026-10-17-cashguard-design.md` (§5 API, §6 интерфейс).
Мок данных: `docs/frontend/mock_details.json` (нарушения), `mock_details_clean.json` (чисто), `mock_details_processing.json` (в процессе).
Поля карточки: `observed` → «Что видно», `why` → «Почему», `rule` → «Норматив» (может быть `null`), `confidence_level` → уровень уверенности.

## 1. Для кого и зачем

- **Проверяющий в банке** загружает запись с камеры кассы и хочет быстро понять:
  есть ли признаки возможного нарушения, где на видео, что видно и на какое правило ссылается вывод.
  Он не доверяет «чёрному ящику» — ему нужны доказательства.
- **Жюри хакатона** оценивает «Готовность продукта» (10 баллов): удобство, надёжность загрузки, понятность результата.
  Плюс интерфейс будет на питчинге — он должен выглядеть как продукт, а не как студенческий прототип.

Главное ощущение: **«спокойный инструмент проверки, которому можно доверять»**.
Не дашборд с графиками и не тревожная «система безопасности» с красными мигалками.

## 2. Ограничения

1. **[жёстко] Работает офлайн.** Сервис переносят во внутреннюю сеть банка: никаких CDN, внешних шрифтов,
   аналитики и запросов наружу в рантайме. Всё собирается в статику.
2. **[жёстко] Отдаётся бэком как статика** с того же домена: FastAPI раздаёт папку сборки на `/`.
   API на том же origin: `/api/v1/...`.
3. **[жёстко] Контракт API — из спеки §5 и `backend/app/schemas.py`.** Для экрана используем `GET /api/v1/jobs/{id}/details`
   (там прогресс, таймлайн, нормативы, `preview_url`). Ответ жюри (`/jobs/{id}`) не трогаем.
4. **[жёстко] Язык интерфейса — русский.**
5. **[жёстко] Только визуальный анализ, без идентификации лиц.** Размытие — план backend/ML,
   а не подтверждённая готовность и не обязательное требование кейса.
6. **[жёстко] Два вердикта и проверяемые доказательства.** Ошибка или неполный ответ не превращаются
   в «нарушений нет». На каждое событие нужны тип, точный таймкод, описание, 1–3 JPEG и источник.
7. **[жёстко] Реальная приёмка отдельно от демо.** Обязательный `/jobs/{id}` и UI `/details`
   описывают один результат. Формат жюри не расширяем; B1 допускает отсутствие точного пункта/цитаты
   в `/details` согласно FAQ31. Публичный URL, пять минут и работа без внешней сети проверяются в F6.

## 3. Стек

| Что | Используем | Почему |
|---|---|---|
| Сборка | **Vite** | быстрый старт, сборка в статику, офлайн из коробки |
| UI | **React 18 + TypeScript** | типы под контракт API ловят ошибки до интеграции |
| Стили | **Tailwind CSS 4** и CSS-переменные в `frontend/src/styles.css` | единая тема Forte для общих компонентов, состояний и адаптива |
| Компоненты | **shadcn/ui** (new-york, Radix) | локальные редактируемые компоненты для элементов управления |
| Иконки | **lucide-react** | одна линейная библиотека, без эмодзи |
| Запросы и опрос | **TanStack Query** (`refetchInterval`) | опрос статуса, ретраи и кэш без самописа |
| Шрифты | **Open Sans**, локальные WOFF2; **JetBrains Mono**, `@fontsource/jetbrains-mono` | интерфейс в типографике референса, моноширинные таймкоды; работают офлайн |

React + Vite выбраны для frontend. Сервер — FastAPI, интерфейс собирается в статику.

Конфигурация shadcn/ui — `frontend/components.json`, исходники общих компонентов —
`frontend/src/components/ui/`. Для F1 доступны Button, Input, Card, Progress, Alert, Badge,
Label и Collapsible; F2 добавляет Dialog для увеличения кадра. Используем их во всех состояниях, редактируем по требованиям продукта
и добавляем новые только при необходимости. Alias `@/` указывает на `frontend/src/`
и согласован в TypeScript и Vite. Tailwind подключён через Vite-плагин.

Структура на твоё усмотрение. Сборка кладётся в `frontend/dist`, бэк раздаёт её.
Для разработки — `vite` с прокси `/api`, `/health`, `/previews` на `127.0.0.1:8000`;
пример `mock_details.json` доступен только в явно выбранном demo-режиме.

## 4. Экран и состояния

Одна страница, один сценарий. Никакой навигации, авторизации, истории.
Компактная шапка GuardTusk и заголовок «Проверка видео». В одной рабочей колонке — только загрузка,
ключ API, статус и результат по задачам Linear; рядом с результатом — примечание о проверке человеком.
Без рекламного hero, боковой колонки с преимуществами, банковских продуктов и большого footer.

### 4.1 Загрузка
- Крупная зона drag-and-drop + кнопка выбора файла. Обязательно принять `.mov` около 29 МБ по кейсу.
  `.mp4` и лимит 200 МиБ — расширение команды; подсказку согласуем с backend.
- Проверка формата и размера до отправки; ошибка — рядом с зоной, с тем, как исправить.
- Поле API-ключа (свёрнуто, если ключ уже сохранён). Ключ — в заголовке `X-API-Key`.
- Прогресс отправки файла в процентах.

### 4.2 Обработка
- Шаги с текущим активным: **Подготовка видео → Люди и предметы → Анализ сцены → Проверка находок**
  (из `progress.stage`, значение — `progress.value`).
- Миниатюра первого кадра или имя файла — чтобы было видно, что обрабатывается.
- Текст «Видео обрабатывается» с прошедшим временем. Оценка 1–2 минуты допустима после реального замера.
  Лимит кейса — получение результата за 5 минут; frontend-таймаут не подтверждает срок сервера.
  При повторе polling время той же задачи не начинается заново; неизвестный этап отображается нейтрально.
- Ошибка или `failed` — причина человеческим языком и кнопка «Попробовать снова».

### 4.3 Результат
Одна колонка на десктопе и мобильном (375 px): баннер → карточки доказательств.
Если включён F3, перед карточками появляется плеер; F4 добавляется после основной приёмки.
Ширина ограничена, чтобы текст и элементы управления оставались удобными для проверки.
Кнопка «Новое видео» возвращает к загрузке. Плашка «Результат — подсказка для проверки человеком»
остаётся частью результата. Карточки F2 обязательны; плеер F3 помогает проверке, дорожки F4 — дополнение.

**Баннер вердикта**
- `violation`: «Обнаружены признаки возможных нарушений: 2» — акцентный цвет + иконка.
- `no_violation`: «Нарушение не обнаружено» — нейтрально-позитивный + иконка.
  «Проверено правил: N» показывается только по достоверным данным сервера.
- Несогласованность вердикта и списка событий — ошибка данных, а не корректный результат.
- Режим заглушки из `/health` и `degraded: true` помечаются явно. Неполный, тестовый
  или неподтверждённый анализ не получает зелёную плашку успешной проверки.
- Не используем слова «виновен», «нарушитель». Формулировки — «признаки возможного нарушения».

**Плеер**
- `<video>` по `preview_url`, на шкале — метки нарушений (интервал `timecode_sec`–`timecode_end_sec`).
- Клик по метке, таймкоду в карточке или кадру-доказательству → перемотка на момент −1 с и подсветка карточки.
- Активная карточка подсвечивается, когда плеер проходит её интервал.
- Отсутствующий/сломанный preview не скрывает обязательные кадры и карточки. Доступ к media согласуем с B3:
  `<video src>` не передаёт `X-API-Key`, основной ключ в URL не помещаем.
- Переход на −1 с даёт контекст; точный таймкод и кадр-доказательство не сдвигаются.

**Дорожки состояний** — дополнительная объяснимость после F6
- Каждая дорожка — интервалы из `timeline`: где кассир на месте, где деньги на столе и т. д.
- Курсор синхронен с плеером, клик по дорожке — перемотка.
- Интервалы, совпадающие с нарушением, подсвечены цветом нарушения.
- Подписи дорожек — по-русски (словарь ключей в мок-файле).
- Только реальные данные backend. Если timeline отсутствует, блок скрываем; F4 не блокирует сдачу.

**Карточка нарушения**
- Заголовок: тип нарушения + таймкод `мм:сс,д` (моноширинные цифры) + уверенность (низкая/средняя/высокая, не проценты).
- Кадры-доказательства: 1–3 настоящих JPEG из API с точным `timestamp_sec`, без обрезания доказательства.
  Клик — просмотр крупно (лайтбокс), Esc закрывает. Повреждённый кадр обозначается явно.
- **Что видно** — описание наблюдаемого.
- **Почему это может быть нарушением** — короткое пояснение правила.
- **Норматив** — название источника, ссылка, пункт/цитата при наличии (длинную цитату можно свернуть).
  FAQ31 допускает источник без точного пункта и открытые документы других банков; юрисдикция — РК.
  Реквизиты не выдумываем. Если `rule:null` — «Источник не указан, требуется проверка»;
  вёрстка работает, но требование о нормативной связи пока не выполнено.
  Название и объяснение доступны без интернета; внешняя ссылка открывается по действию пользователя.
- Типы из API не ограничиваем примерами. Пустые объяснения, некорректные JPEG и противоречивый ответ
  не превращаются в ложный успешный анализ. Пример цитаты из мока не выдаём за проверенный норматив.

## 5. Визуальное направление

**Стиль:** минимальный светлый интерфейс проверки в визуальном стиле [Forte](https://forte.kz/ru).
Используем его палитру, Open Sans и скругления: 12 px у кнопок, 24–32 px у основных секций.
Белые и светло-серые поверхности, спокойные границы, без декоративных блоков.

**Цвета (канонические shadcn-переменные, не хардкод в компонентах):**

| Токен | Светлая | Назначение |
|---|---|---|
| `--background` | `#F7F6F6` | фон страницы |
| `--card` | `#FFFFFF` | карточки, панели |
| `--secondary`, `--muted` | `#EDEDED` | вторичные поверхности |
| `--foreground` | `#1D1D1D` | основной текст |
| `--primary` | `#4A0221` | основная кнопка |
| `--brand` | `#A31551` | выраженные акценты и активные состояния |
| `--accent` | `#FBEDF3` | мягкая подсветка при наведении |

Цвет никогда не единственный носитель смысла: всегда иконка или текст рядом.
Светлая тема задаётся в `frontend/src/styles.css` и применяется к shadcn/ui через Tailwind.
Старые переменные раскладки (`--bg`, `--surface`, `--text` и другие) ссылаются на эту тему,
отдельную палитру для них не создаём. Тёмная тема не используется.
Семантические цвета ошибок, находок и успешного результата остаются отдельными токенами
в `frontend/src/styles.css`; текст на поверхностях должен сохранять контраст ≥ 4.5:1.
Продукт называется GuardTusk. Название и логотип ForteBank, его банковские функции и навигацию не переносим.

**Типографика:** Open Sans variable 300–800 для интерфейса; WOFF2, источники и лицензия OFL хранятся
в `frontend/src/assets/fonts/` и входят в сборку. JetBrains Mono из локального пакета `@fontsource/jetbrains-mono`
остаётся для таймкодов, времени и процентов с табличными цифрами.
Шкала 12 / 14 / 16 / 20 / 24 / 32. Текст 16 px, межстрочный 1.5.

**Отступы:** сетка 4/8 px; между секциями 24–32 px; одна рабочая колонка шириной до 800 px.

**Движение:** 150–250 мс, только смена состояний и подсветка карточки; уважать `prefers-reduced-motion`.

## 6. Качество (проверим перед сдачей)

- [ ] Доступность: фокус видим, всё работает с клавиатуры (загрузка, плеер, лайтбокс, ссылки), контраст ≥ 4.5:1.
- [ ] 375 px без горизонтальной прокрутки; 1440 px не растягивается в ленту.
- [ ] Нет «прыжков» вёрстки при загрузке кадров: размеры миниатюр заданы.
- [ ] Ошибки сети, `401`, `400`, `failed`, таймаут — у каждой понятный текст и действие.
- [ ] Видео с 0, 1 и 3+ нарушениями выглядят аккуратно; длинные описания и цитаты не ломают карточку.
- [ ] Источник без пункта и `rule:null`, новый тип, повреждённый кадр и недоступное превью обработаны честно.
- [ ] Сборка и анализ работают без внешнего интернета, с доступом браузера к локальному сервису.
- [ ] Реальный MOV проходит через публичный UI/API за ≤5 минут; две API-проекции и кадры согласованы (F6).
